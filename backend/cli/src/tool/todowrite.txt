Maintain a visible task list for work with three or more meaningful steps, multiple user requirements, or when the user explicitly asks for a plan or todo list. Skip it for a single short action, a trivial request, or purely conversational work.

Send the complete current list on every update and keep item IDs stable. Use concrete, actionable items with `pending`, `in_progress`, `completed`, or `cancelled` status and `high`, `medium`, or `low` priority. Keep at most one item `in_progress`. Mark finished work `completed` before advancing, retain unfinished items, and mark obsolete items `cancelled` rather than silently removing them. Keep the list concise so tracking does not become work of its own.

Update the list in the same step as the work it reports: call this tool alongside the next tool call (a run, a read, an edit), not as a step of its own. A step whose only call is a todo update adds a full model round-trip and shows the user nothing new.
